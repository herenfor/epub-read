# B-061/C-50：实验性相邻章节预渲染

- 状态：代码、自动化与 WSL Chromium 实书回归完成，待用户和 Windows WebView2 审核，尚未同步。
- 目标：增加默认关闭的“高性能模式”。当前可重排章节完成显示后，使用同尺寸离屏 iframe 依次完整准备下一篇、上一篇 linear 章节；顺序跨章命中时直接提升已准备槽位，未命中无条件回退现有加载路径。
- 非目标：不整书渲染、不预测目录/搜索/笔记/历史跳转、不支持 fixed-layout、不做翻页动画、不持久化分页结果。
- 核心约束：调度独立、分页核心复用。只有当前可见 paginator 能发送页码、进度、display-ready、链接、脚注、选区和翻页事件；预渲染 paginator 静默。标准模式必须保持原单 iframe 路径。
- 失效：章节目标、书籍会话、阅读区尺寸、设置/字体、自定义 CSS变化，或关闭模式、切书、返回书架、dispose 时，取消并释放预渲染槽位及局部 Blob。
- 预计修改：`src/ui/ReaderView.tsx`、新增预渲染纯逻辑及测试、设置/菜单/存档文件、必要的 `ChapterPaginator` 安全接口、样式和维护文档。
- 实现：`ReaderView` 管理最多三个重叠槽位（上一篇/当前篇/下一篇）；备用 paginator 复用完整 `loadAndWaitForDisplay()` 准备链，并严格按下一篇优先、上一篇随后执行，避免两个完整分页任务并发抢占 CPU。所有构造回调以 active slot 身份门控；React 提交新 spineIndex 后才提升槽位并发布 ready。旧活动槽保留为反向缓存，新远端相邻章再进入空闲槽。显式目录/搜索/书签/笔记/历史跳转不得误用相邻缓存。仅开关变化不重载当前章；其他渲染设置、字体与阅读区尺寸变化取消旧预载。尺寸监听绑定稳定阅读器容器，槽位提升本身不会清空刚保留的反向缓存。
- 验收结果：标准关闭为 1 个 iframe，开启最多为 3 个，且始终只有一个可见/可交互；全量 Vitest 51 files/402 tests、TypeScript 与 Vite build（110 modules）通过。WSL Chromium 1100×760 使用《ePub指南——从入门到放弃》：首章正确保持“当前+下一篇+空闲槽”；进入第二章后三个 Blob 文档分别对应上一篇/当前篇/下一篇，返回上一章约 7ms 并命中原活动 Blob。纸色详细设置使用统一浅卡片和现代开关；后续窄窗回归进一步确认滑块/开关卡片均为 267×60，`+` 按钮右缘留在卡片内约 11px，开关标题不再继承滑块的顶部内边距。临时脚本/截图已删除，5173 已释放。
- 未验证：Windows WebView2 的 CPU/内存曲线、图片大章、连续快速跨十章和系统休眠/窗口最小化恢复仍待用户实机。
