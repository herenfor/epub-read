# SeLis AUR package (candidate)

**Status: candidate only.** This package has not been uploaded to the AUR, no
package name has been registered, and upstream has no release tag containing
the Linux host yet (`v0.4.0` predates it and `v0.4.1` is not released). Do not
treat it as an official download channel.

The package builds the Linux Core host from source on x86-64. It does not
download a prebuilt binary and does not modify the application source.

## Package layout

- `pkgname=selis`, `arch=('x86_64')`, `license=('GPL-3.0-only')`.
- The package name is `selis`; the binary, desktop entry and icons keep the
  names produced by the existing Tauri Linux bundle (`epub-reader`,
  `SeLis.desktop`). This keeps the desktop entry and GTK window class coherent.
- Installed paths:

| Path | Content |
| --- | --- |
| `/usr/bin/epub-reader` | release binary built by `scripts/build-linux.sh --no-bundle -- --locked` |
| `/usr/share/applications/SeLis.desktop` | `Exec=epub-reader %U`, `StartupWMClass=epub-reader`, `MimeType=application/epub+zip;` |
| `/usr/share/icons/hicolor/{32x32,128x128,256x256}/apps/epub-reader.png` | icons from `src-tauri/icons/` |
| `/usr/share/licenses/selis/` | `LICENSE`, `LICENSING.md`, `NOTICE`, `THIRD_PARTY_LICENSES.md` and `third-party-licenses/` |

`application/epub+zip` is provided by `shared-mime-info`; this package does
not install its own MIME XML. Desktop/MIME caches are refreshed by the pacman
hooks from `desktop-file-utils`, `shared-mime-info` and
`gtk-update-icon-cache` (all pulled in by `gtk3`; the first two are also
listed in `depends` because the package's desktop entry and MIME declaration
rely on them).

## Source archive

Upstream has no release tag that contains the Linux host yet, so the
`source` field points to a local archive generated from a pinned commit:

```bash
git archive --format=tar --prefix=selis-0.4.1/ \
  7081619dfae5a12b0ec8b29425d2d5d2f5175548 | gzip -9n > selis-0.4.1.tar.gz
sha256sum selis-0.4.1.tar.gz
```

Expected:

```text
3fe07603ade4b3928a579e5e4a9a3ce7000afdb1d1da7052ee27b63a78d3a1c8  selis-0.4.1.tar.gz
```

The archive is not part of Git. The checksum in `PKGBUILD` is the checksum of
this exact archive and is still verified by `makepkg`. It is not an upstream
download and must not be uploaded as an AUR source. When a release tag with
Linux support exists, replace `source` with the official tag archive URL,
update `sha256sums`, and regenerate `.SRCINFO`.

## Dependencies

Package names and availability were checked against the Arch official
repositories and the actual release binary; versions are not minimums.

| Type | Packages |
| --- | --- |
| Runtime (direct ELF or desktop integration) | `cairo`, `dbus`, `fontconfig`, `gcc-libs`, `gdk-pixbuf2`, `glib2`, `gtk3`, `hicolor-icon-theme`, `libsoup3`, `webkit2gtk-4.1`, `xdg-utils` |
| Build | `rust` (provides `cargo`), `nodejs`, `pnpm`, `pkgconf`; `makepkg` also requires the standard `base-devel` tools |

`gtk3` pulls in `desktop-file-utils`, `shared-mime-info`, `gtk-update-icon-cache`
and `pango`; `desktop-file-utils` and `shared-mime-info` are still listed
explicitly because the package's desktop/MIME entries rely on their update
hooks. `webkit2gtk-4.1` also provides the `javascriptcoregtk-4.1` library used
by the binary. The build entry checks the `gtk+-3.0`, `webkit2gtk-4.1` and
`fontconfig` pkg-config modules.

Versions observed in the isolated build environment (2026-11-06) include
`gtk3 3.24.52`, `webkit2gtk-4.1 2.54.2`, `fontconfig 2.18.3`, `rust 1.99.1`,
`nodejs 26.13.0`, `pnpm 12.17.0`, `pkgconf 3.0.10` and `makepkg 7.1.0`.

## Build and install

In a clean Arch x86-64 environment, put `selis-0.4.1.tar.gz` next to the
`PKGBUILD` and run:

```bash
makepkg --printsrcinfo > .SRCINFO
makepkg -sri
```

`build()` runs the existing build entry:

```text
pnpm install --frozen-lockfile --store-dir "$srcdir/pnpm-store"
bash scripts/build-linux.sh --no-bundle -- --locked
```

Rust output is placed in `$srcdir/target`; `package()` installs only the
release binary, icons, desktop entry and license files listed above. There is
no background service, no database/library hook and no global npm/pnpm
installation.

After installation, check:

```bash
pacman -Ql selis
desktop-file-validate /usr/share/applications/SeLis.desktop
gio mime application/epub+zip
readelf -d /usr/bin/epub-reader | grep NEEDED
```

Then open a synthetic EPUB from a file manager or through `gio open` to check
that `%U` passes the path to the app.

## Validation

- `.SRCINFO` is generated by Arch `makepkg --printsrcinfo`; the checked-in file
  matches this `PKGBUILD` and is not hand-written.
- `makepkg` validated the pinned local source against `sha256sums`.
- The package metadata passed `namcap PKGBUILD`, and dependency resolution
  reached the build stage in the isolated Arch x86-64 environment.
- The isolated Arch x86-64 source build and `pacman -U` installation passed.
  The installed desktop entry, ELF dependencies, icons and license files were
  checked; this does not prove GUI or file-manager integration.
- The initial build failed because makepkg's default GCC LTO left GCC-only
  bitcode in bundled C archives, which Rust's lld could not link. `!lto` disables
  that packaging flag; the application's Rust release LTO remains enabled.
- Not verified: launching the native
  window on a physical Arch desktop, file-manager association,
  upgrade/removal, the minimum supported Arch snapshot, and any AUR
  publication.

Do not upload this package until a release tag containing the Linux host
exists, the source URL and checksum point at that release, and a maintainer
has repeated the build and desktop checks on an Arch desktop with a working
Rust toolchain.

## Before publishing

1. Use the official release tag archive as `source` and update
   `sha256sums`; regenerate `.SRCINFO`.
2. Re-run `makepkg --printsrcinfo` and `makepkg` for the final release source.
3. Verify the desktop entry, icon, EPUB MIME association and install/removal
   behavior on a target Arch desktop.
4. Get explicit authorization before registering or uploading to the AUR; do
   not push, tag or change the product version as part of this candidate.
